## 架构议题

### T-17：Checkpoint-Resume 机制

**当前状态：不存在。** 项目中所有脚本均无中间状态持久化。每次运行 `convert.py` 都是全量重跑（probe → preprocess → pandoc → pipeline → write）。

**影响场景：**
- 批量转换中途中断，需从头重跑
- 大型文档 pandoc 耗时长，pipeline 阶段失败无法接续
- Agent 调用超时后进度全部丢失

**建议设计（Backlog，供后续讨论）：**

在 `convert.py --batch 目录/` 模式下引入 `.tencdoc_checkpoint.json`：

```json
{
  "batch_id": "2026-04-12T05:55",
  "files": {
    "文件A.docx": { "status": "done", "output": "...", "sha256": "abc..." },
    "文件B.docx": { "status": "pending" },
    "文件C.docx": { "status": "failed", "error": "pandoc timeout" }
  }
}
```

重跑时跳过 `status=done` 且文件 hash 未变的条目。单文件转换当前足够快，此功能优先级低。
